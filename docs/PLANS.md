# Engineering plans

Use a plan for work that spans multiple files, introduces a public contract, changes evidence semantics, adds a dependency, or takes more than one focused implementation pass.

A plan is a living source of truth for the milestone. Keep it updated as reality changes.

## Goal
What observable capability becomes true?

## Non-goals
What tempting adjacent work is explicitly excluded?

## Sources / authority
Which specs, papers, reference implementations, ADRs, or fixtures govern behavior?

## Current state
What exists before this change?

## Design
Smallest architecture that satisfies the goal.

## Acceptance criteria
Concrete behavior/tests/artifacts.

## Implementation steps
Ordered, independently verifiable slices.

## Validation
Exact commands, fixtures, differential checks, or benchmarks.

## Risks / open questions
Scientific/engineering uncertainty that must not be hand-waved.

## Outcome
After implementation: what actually changed, checks run, deviations, follow-ups.
