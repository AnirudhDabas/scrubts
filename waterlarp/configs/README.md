# Configuration profiles

The CPU profile is a real integration PILOT only after `execution_status` is
updated by a successful canonical run. Its tiny N cannot resolve 1% empirical
FPR and its model is not suitable for headline quality conclusions.

The paper profile is a frozen scale proposal. `NOT_EXECUTED` is semantic data,
not a comment. Model revisions and operation-model revisions must be pinned
before execution. The 0.1% target requires at least 1,000 negatives merely to
reach the empirical grid; robust confidence at that target generally requires
more, so a power calculation is mandatory before approval.

`sample_count_per_split` is not a runner constant. Every task may select any
positive N supported by its bounded source population, and the manifest stores
all exact members. The CPU profile requests N=2 only as an end-to-end
multi-member integration proof. Paper-plan counts validate structurally but are
not executed by the pilot command.
